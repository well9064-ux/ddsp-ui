드론 파종 서비스 시나리오

농가·법인이 자기 드론을 등록하고 필지를 신청해 직접 파종하고, 대동은 처방 분석 · 업로드와 임무 전송을 맡습니다. 드론 등록(0단계)부터 영농일지 기록(8단계)까지 누가 어떤 화면에서 무엇을 하는지 정리했습니다.

이 시나리오의 요점

신청과 운용은 농가·법인, 처방과 전송은 대동농가·법인이 자기 필지를 신청하고 자기 드론으로 파종합니다. 대동 관리자는 신청을 확인해 필지 정보로 처방을 만들고(신청별 센서 비행 없음) 임무를 보냅니다.
임무는 필지 주인의 등록 드론으로처방맵을 올리면 필지 소유 농가·법인이 등록한 드론이 전송 대상으로 자동 지정됩니다. 관리자는 전송 전 확인 창에서 필지 · 드론 · 처방 · 예상 파종량을 한 번 더 보고 보냅니다.
농가는 처방과 예상 파종량을 지도로필지 모니터링의 '드론 파종' 탭에서 6m 격자 처방과 총 · 등급별 예상 파종량, 내 드론으로 보낸 임무를 봅니다.
결과는 영농일지에 작업 전 · 작업 후로파종이 끝나면 영농일지에 작업 전(처방맵)과 작업 후(드론 파종 경로) 지도가 자동으로 남고, 현장조사 값을 이어서 입력합니다.

1. 전체 흐름

세로선은 주체, 상자는 단계입니다. 초록 상자(4 전송 전 확인, 6 처방 · 예상 파종량 확인)는 이번 시나리오로 새로 만든 화면입니다. 상자 아래 색 글자는 그 단계의 진행 상태입니다.

3. 상태값

같은 일을 보는 사람에 따라 세 가지 상태로 보여줍니다.

농가 화면 진행 표시
신청→요청→처방→파종→완료
필지 모니터링 › 드론 파종 탭. 신청은 농가가 누른 시점, 요청은 대동이 확인해 처방 분석을 요청한 시점입니다.
정밀진단 관리 (관리자)
요청→처방→파종→완료
신청 목록의 진행 상태. 처리 열은 상세 · 결과 등록입니다.
임무 관리
수행 대기→수행 중→중단→완료
임무를 보낸 뒤부터의 상태. 하루에 못 끝내면 중단 후 다음 날 이어서 하고, 중단 이유는 받을 수 없어 표시하지 않습니다. 수행 대기 임무만 수정 · 삭제할 수 있습니다.

4. 정한 것

  1. 임무 전송 대상. 농가·법인이 기체 관리에서 자기 드론을 등록하고, 처방맵을 올리면 필지 소유자의 등록 드론이 자동으로 지정됩니다. 여러 대면 관리자가 고르고, 미등록이면 보낼 수 없습니다.
  2. 전송 전 확인. 처방맵 업로드 후 확인 창에서 필지 · 드론 · 처방 · 예상 파종량 · 비행 조건을 확인하고 임무를 보냅니다.
  3. 처방 · 예상 파종량 보는 곳. 농가 필지 모니터링 '드론 파종' 탭 지도에 보여줍니다.
  4. 센서 비행 없음. 처방 분석은 필지 정보로 하고, 신청마다 센서 비행을 하지 않습니다.
  5. 신청은 농가·법인. 대동 관리자가 신청을 확인해 처방 분석을 요청합니다.
  6. 임무 상태와 중단. 수행 대기 · 수행 중 · 중단 · 완료 네 가지로 두고, 중단 이유는 표시하지 않습니다.
  7. 영농일지. 드론 작업 기록을 작업 전(처방맵) · 작업 후(파종 경로) 지도로 나눠 남깁니다.

5. 남은 확인 사항

락로보틱스

  • 임무를 조종기 식별자로 보내는지, 농가가 입력한 식별자가 GCS 서버에 있는지 조회할 수 있는지
  • 수행 대기 임무를 삭제 · 수정할 때 GCS 서버와 조종기에서 회수 · 교체할 수 있는지

대동 내부

  • 드론을 등록하지 않은 농가·법인의 신청을 받을지(신청 때 드론 등록 필수 여부)
  • 드론이 여러 대인 법인의 필지별 기본 드론 지정 방식
  • 처방 대상 선정 기준과 대상이 되지 않은 신청 건 안내

KETI

  • 신청별 센서 비행 없이 생육 · 토양 드론 레이어(NDVI · DEM)를 어떤 데이터로 언제 채울지

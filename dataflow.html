드론 파종 플랫폼 · 인터페이스 설계 v0.6 · 2027 Pilot 범위 · 2026.10.20

드론 파종 플랫폼 데이터 흐름도 논의 필요 · 협의 후 확정

락로보틱스·KETI·경상국립대 데이터가 기존 대동 커넥트(정밀농업)와 신규 드론 모듈 사이를 어떻게 흐르는지 정리했습니다. 근거는 과제 계획서, 9/17 미팅자료, 개발계 관리자·농민 사이트 조회 결과입니다. 주기·포맷·프로토콜은 1차년도 API 명세에서 확정할 제안값입니다.

이 흐름도의 요점

새로 만드는 자동 연동은 GCS 한 곳실시간 텔레메트리·이벤트(IF-01~04)만 Pilot('27)부터 자동입니다. KETI 맵레이어와 경상대 처방맵은 Pilot 동안 기존 '데이터 등록' 화면으로 수동 등록하고, 자동 수신(IF-05·06)은 '28년 이후로 전환합니다.
기존 대동 커넥트 위에 얹는 구조필지·필지 ID, 고객·보유 차량, 진단 레이어, 영농일지, 이벤트 코드·App Push, 조직·이력은 이미 있습니다. 신규는 드론 모듈(수집·임무·관제·이력·자산) 하나로 모입니다.
작업 결과는 자동 영농일지로 기록드론 작업이 끝나면 텔레메트리로 영농일지의 '드론 작업 기록'을 자동 작성하고, 현장조사 값을 이어서 입력합니다. '27 실증은 연구원·조종사가 운용하므로 기존 대행 흐름(공고·매칭·승인·정산)에 연결하지 않습니다(v0.2).
플랫폼이 허브필지 경계·ID(IF-10)를 세 기관에 같은 기준으로 내주고, 처방 버전과 실제 투입량을 플랫폼에서 연결합니다. 기관끼리 직접 주고받으면 이 추적이 끊깁니다.
드론은 정밀농업 › '드론 관리' 메뉴차량관리·차량유지관리는 농기계 전용이라 드론을 넣지 않습니다. 정밀농업 아래 신규 '드론 관리' 메뉴(상단 탭: 드론 현황·기체 관리·임무 관리·작업 이력)에서 기체(GCS 기체 식별자)·파종 모듈·배터리·정비 이력을 관리하고, 고객·조직 마스터만 참조합니다. 소유 주체(법인·농민·실증 운영자)는 아직 미정입니다.

1. 시스템 구성과 데이터 흐름

초록 테두리는 이번 사업에서 새로 만드는 부분, 점선 테두리는 개발계에 이미 있는 기능입니다.

2. 임무 1건의 데이터 시퀀스

분석 신청부터 리포트까지 19단계입니다. 단계 번호 옆의 ID는 아래 인터페이스 목록과 연결됩니다.

5. 다음 협의에서 결정할 것

기관별 협의 사항과 대동 내부에서 정할 것을 나눴습니다. 락로보틱스 항목을 먼저 정해야 GCS 연동(IF-01~04) API 명세를 쓸 수 있습니다.

5-1. 기관별 협의 사항

락로보틱스 IF-01~04

  • 비행 경로 생성 주체(GCS vs 플랫폼)와 파종 조건의 최종 입력 위치 — GCS가 만들면 IF-03에 Waypoint 업로드, 플랫폼이 만들면 IF-01 임무 파일에 경로 포함
  • 텔레메트리 필드·단위·주기, 전송 방식(MQTT/WebSocket)과 브로커 위치(대동 커넥트 인프라 가능 여부)
  • 이벤트 코드표, 파종량 위치 태깅 방식(1초 주기 RTK 위치 동반 여부)
  • 기체 식별자·인증 토큰 발급·갱신, 통신 단절 시 재전송·중복 제거
  • 플랫폼에서 기체로의 명령(일시정지 등) 허용 여부 — 현재 IF에 명령 경로 없음

KETI IF-05 · IF-12

  • 드론 정밀 촬영 수행 주체(KETI vs 락로보틱스)와 파종 후 촬영을 실증 프로토콜에 넣을지
  • 맵레이어·DEM 파일 포맷, 촬영 메타데이터 항목, 좌표계
  • 촬영 요청(IF-12) 수신·회신 방식

경상국립대 IF-06

  • 처방맵 규격: 구역 단위·최소 구간 면적, 3단계 값 표현, SHP/GeoJSON, 버전 규칙
  • 현장조사 항목·조사 시점과 결과 회신 양식(CSV)
  • 처방 반려 시 재산출 요청 경로
  • 경제성 평가 양식·산식과 평가 수행 기관

공통 IF-10

  • 필지 정보 제공(IF-10) 방식·좌표계, 촬영·처방·임무 결과에 같은 필지 ID 부여
  • 허브 구조: KETI 맵레이어가 경상대로 직접 가지 않고 플랫폼을 거치도록 3개 기관과 합의
  • 일정 불일치 정리(계획서 28/24주 vs 미팅자료 20/16주)

5-2. 대동 내부에서 정할 것

  1. 드론 소유 주체. 드론은 정밀농업 › 드론 관리 메뉴에서 GCS 기체 식별자로 관리합니다(v0.6). 남은 것은 기체를 법인(농협)·농민·실증 운영자 중 누구 소유로 연결할지와, 영농일지 작업차량 선택에 드론을 어떻게 보여줄지입니다.
  2. 실증 작업 결과 확정 절차. 대행 흐름을 쓰지 않으므로, 자동 영농일지와 현장조사 값을 누가(연구원·대동 담당자) 확인·확정할지 정합니다.
  3. 위성 데이터 범위. 계획서에 위성 데이터가 없습니다. 기존 위성 기본·정밀 결과를 드론 결과와 비교만 할지 정합니다.
